# gpl-hub:release-please@1
# Gerado pelo GPL HUB (https://github.com/devGPL/HUB). Ajuste à vontade para o projeto.
name: Release Please

# A cada merge na main, mantém aberta uma PR de release com versão e changelog.
# Ao mergear essa PR, a tag e o GitHub Release são criados.
on:
  push:
    branches: [main]

permissions:
  contents: write
  pull-requests: write

jobs:
  release-please:
    runs-on: ubuntu-latest
    steps:
      - uses: googleapis/release-please-action@v4
        with:
          token: ${{ secrets.GITHUB_TOKEN }}
          # A branch padrão pode ser dev: sem isto a PR de release nasceria lá.
          target-branch: main
          config-file: release-please-config.json
          manifest-file: .release-please-manifest.json

Sync dev

Adiciona.github/workflows/sync-main-to-dev.yml
# gpl-hub:sync-dev@1
# Modelo gerenciado pelo GPL HUB (https://github.com/devGPL/HUB). Mudanças aqui devem ir para o modelo.
name: Sync main to dev

# Toda vez que algo entra na main (merge da release, hotfix), leva para a branch de
# integração (dev ou develop). Usa `push` e não `release: published` porque releases
# criadas pelo GITHUB_TOKEN do release-please não disparam outros workflows.
#
# Ordem de tentativa: fast-forward, merge comum e, se houver conflito ou a branch
# estiver protegida, abre uma PR para resolver na mão.
#
# Requer em Settings > Actions > General: "Allow GitHub Actions to create and approve pull requests".

on:
  push:
    branches: [main]
  workflow_dispatch:

permissions:
  contents: write
  pull-requests: write

concurrency:
  group: sync-main-to-dev
  cancel-in-progress: false

jobs:
  sync:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0

      - name: Descobrir a branch de integração
        id: target
        run: |
          for b in dev develop; do
            if git ls-remote --exit-code --heads origin "$b" > /dev/null; then
              echo "branch=$b" >> "$GITHUB_OUTPUT"
              exit 0
            fi
          done
          echo "Nenhuma branch dev ou develop encontrada; nada para sincronizar."
          echo "branch=" >> "$GITHUB_OUTPUT"

      - name: Sincronizar
        if: steps.target.outputs.branch != ''
        env:
          GH_TOKEN: ${{ secrets.GITHUB_TOKEN }}
          TARGET: ${{ steps.target.outputs.branch }}
        run: |
          set -u
          git config user.name "github-actions[bot]"
          git config user.email "41898282+github-actions[bot]@users.noreply.github.com"
          git fetch origin main "$TARGET"

          if git merge-base --is-ancestor origin/main "origin/$TARGET"; then
            echo "$TARGET já contém a main."
            exit 0
          fi

          git checkout -B "$TARGET" "origin/$TARGET"

          if git merge --ff-only origin/main && git push origin "$TARGET"; then
            echo "Fast-forward aplicado."
            exit 0
          fi

          git reset --hard "origin/$TARGET"
          if git merge --no-ff origin/main -m "chore: sync main to $TARGET" && git push origin "$TARGET"; then
            echo "Merge aplicado."
            exit 0
          fi

          echo "Não deu para aplicar direto; abrindo PR."
          git merge --abort 2>/dev/null || true
          BRANCH="chore/sync-main-to-$TARGET"
          git checkout -B "$BRANCH" origin/main
          git push --force origin "$BRANCH"

          if gh pr list --head "$BRANCH" --base "$TARGET" --state open --json number --jq 'length' | grep -q '^0$'; then
            gh pr create --base "$TARGET" --head "$BRANCH" \
              --title "chore: sync main to $TARGET" \
              --body "Sync automático da \`main\` para \`$TARGET\`. O merge direto falhou (conflito ou branch protegida); resolva e faça o merge."
          fi
  • Em Settings > Actions > General, habilite "Allow GitHub Actions to create and approve pull requests" para o workflow conseguir abrir PR quando houver conflito.

Adiciona.github/workflows/notify-discord-pr.yml
# gpl-hub:discord-pr@1
# Modelo gerenciado pelo GPL HUB (https://github.com/devGPL/HUB). Mudanças aqui devem ir para o modelo.
name: Notifica PR no Discord

# Avisa o PO no canal compartilhado quando uma PR fica pronta para revisão.
# O nome do repositório vai em destaque e cada repo tem uma cor fixa, para dar
# para saber de onde veio a PR sem abrir o link.
#
# Configuração no próprio repositório (no plano Free, secrets da organização não chegam a repos privados):
#   - Secret   DISCORD_WEBHOOK_URL : webhook do canal de notificação
#   - Variable DISCORD_PO_USER_ID  : ID do usuário do PO no Discord, para a menção
#                                    (DISCORD_PO_ID também é aceito, nome antigo do DataBook)

on:
  pull_request:
    types: [opened, ready_for_review, reopened]

permissions:
  contents: read

jobs:
  notify:
    runs-on: ubuntu-latest
    if: ${{ github.event.pull_request.draft == false }}
    steps:
      - name: Postar no Discord
        env:
          WEBHOOK: ${{ secrets.DISCORD_WEBHOOK_URL }}
          PO_ID: ${{ vars.DISCORD_PO_USER_ID || vars.DISCORD_PO_ID }}
          REPO: ${{ github.event.repository.name }}
          REPO_URL: ${{ github.event.repository.html_url }}
          NUMBER: ${{ github.event.pull_request.number }}
          TITLE: ${{ github.event.pull_request.title }}
          URL: ${{ github.event.pull_request.html_url }}
          AUTHOR: ${{ github.event.pull_request.user.login }}
          AVATAR: ${{ github.event.pull_request.user.avatar_url }}
          BASE: ${{ github.event.pull_request.base.ref }}
          HEAD: ${{ github.event.pull_request.head.ref }}
        run: |
          if [ -z "$WEBHOOK" ]; then
            echo "DISCORD_WEBHOOK_URL não configurado; pulando notificação."
            exit 0
          fi

          MENTION=""
          if [ -n "$PO_ID" ]; then MENTION="<@$PO_ID> "; fi

          # Cor fixa por repositório, escolhida pelo hash do nome.
          PALETTE=(3066993 3447003 15105570 15277667 1752220 16776960 10181046 15548997 2067276 12745742)
          HASH=$(printf '%s' "$REPO" | cksum | cut -d' ' -f1)
          COLOR=${PALETTE[$((HASH % ${#PALETTE[@]}))]}

          jq -n \
            --arg content "${MENTION}nova PR em **${REPO}** para revisar" \
            --arg repo "$REPO" \
            --arg repo_url "$REPO_URL" \
            --arg title "#${NUMBER} ${TITLE}" \
            --arg url "$URL" \
            --arg author "$AUTHOR" \
            --arg avatar "$AVATAR" \
            --arg branch "${HEAD} → ${BASE}" \
            --argjson color "$COLOR" \
            '{
              content: $content,
              allowed_mentions: { parse: ["users"] },
              embeds: [{
                author: { name: $repo, url: $repo_url },
                title: $title,
                url: $url,
                color: $color,
                thumbnail: { url: $avatar },
                fields: [
                  { name: "Autor", value: $author, inline: true },
                  { name: "Branch", value: $branch, inline: true }
                ]
              }]
            }' \
            | curl -sf -H "Content-Type: application/json" -d @- "$WEBHOOK"
  • O workflow lê o secret DISCORD_WEBHOOK_URL e a variável DISCORD_PO_USER_ID, configurados no próprio repositório (no plano Free, os da organização não chegam a repos privados). Sem eles, o workflow só pula a notificação.

  pull_request:

  pull-requests: read

  lint:

          GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}
